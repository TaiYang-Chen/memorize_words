# 封面模板

`cover-template.html` 是固定 1920 x 1080 的可编辑源文件，`render_cover.py` 是不访问网络的离线 PNG 渲染器。二者都把右侧手机画面留给真实实机截图，不使用仓库首页吉祥物冒充运行时桌宠。

封面只回答一个问题：**背过的词，真的会跟到刷手机的地方吗？** 主文案固定为“背过的词 / 跟着我刷手机”，小标固定为“词源：已学词”。右侧实机截图必须同时给出其他 App、桌宠与真实已学词卡三个证据。

## 替换步骤

1. 在实体手机打开一个无隐私内容的其他 App，让桌宠和真实单词卡同时出现，截取完整竖屏画面。
2. 选择桌宠和单词卡占据屏幕可见主体的截图；裁掉系统通知中的敏感信息，但不要拼接或伪造位置。
3. 保存为 `cross-app-screenshot.png`，建议保留手机原生竖屏分辨率。
4. 模板已固定使用“炫羲单词”；仅在制作其他品牌素材时才修改品牌文字。
5. 先导出草稿检查构图：

   ```powershell
   python ./doc/bilibili_launch/cover/render_cover.py
   ```

6. 真实截图就绪后导出最终封面：

   ```powershell
   python ./doc/bilibili_launch/cover/render_cover.py --final
   ```

7. 确认 `cover-final.png` 为 1920 x 1080，底部没有 `DRAFT` 横条，再运行发布校验。

## 盲测与边界

- 将封面缩小到 320 x 180，并交给 5 至 8 名目标用户看 2 秒。至少 4 人应能说出“桌宠在其他 App 上展示已学词”；否则优先重裁截图，不加更多卖点文字。
- 最终封面只保留两行主文案、词源小标、手机实机画面和桌宠/角色四个主视觉元素。不堆放专项练习、统计、同步或内测招募等次要信息。
- 不把仓库首页或统计页的角色插画当作跨 App 能力证明；真实截图才是产品证据。
- 旧 WebP 角色包正在被 GPU/KTX2 方案替换，封面桌宠以当前候选包实机画面为准。
- 没有真实截图时，渲染器会保留草稿提示或拒绝最终导出；最终导出固定使用“炫羲单词”。`validate.ps1 -Mode Release` 还会检查最终封面尺寸以及截图文件是否存在。
