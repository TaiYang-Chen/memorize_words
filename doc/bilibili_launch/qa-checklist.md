# 发布与内测验收清单

## 1. 品牌与候选包门槛

- [ ] 已以“炫羲单词”完成同名 App、商标、主要应用市场和 Bilibili 站内基础检索。
- [ ] App 标题、启动入口、首页、关于页、系统最近任务、通知标题、安装后桌面名称、APK 文件名、账号资料和所有公开文案均使用同一新名称。
- [ ] 视频、封面、字幕、投稿简介和私信模板中不再出现旧名或未替换的品牌占位符。
- [ ] 当前角色包和 GPU 动画改动已经进入准备发布的确定版本，不使用 7 月 17 日旧 APK。
- [ ] `versionName` 与 `versionCode` 已更新；正式签名 release 构建、核心单元测试和静态检查通过，结果与构建提交号一并保存。
- [ ] 已在一台干净设备上通过统一下载地址安装候选包，并完成 APK SHA-256 的构建侧与下载侧两次比对。
- [ ] 已由 `release-info.template.txt` 生成完整 `release-info.txt`，没有占位符。

## 2. 实体手机全流程冒烟

- [ ] Android 7.1+ 的最低版本或接近最低版本设备可安装并进入核心流程；至少一台目标主力版本设备完成登录、选书、计划、学习、专项练习、统计和同步。
- [ ] 桌宠在其他 App 上显示稳定，权限拒绝与再次授权流程正常；拖动贴边、换词、收藏、复制、关闭和详情入口均正常。
- [ ] 当前角色首次下载正常；下载完成并断网后角色仍可运行。
- [ ] 主学习中故意答错的词会在本轮稍后重新出现，完成后复习状态有真实变化。
- [ ] 听力两种流程、跟读录音/原声/回放/真实云评分、拼写字母池/键盘/提示/手写草稿、随身听后台播放均已在实体机完整走通。
- [ ] 统计页周趋势、日历和某日明细与真实操作一致；飞行模式下记录保留，恢复网络后自动重试成功。
- [ ] 每日签到确实获得 1 天体验；悬浮权益过期和云评分额度用尽时提示准确。

## 3. 拍摄与真实性

- [ ] 所有原始录屏按 `media-manifest.csv` 命名并放入 `media/raw/`。
- [ ] `B01` 与 `B02` 保留同一段未重排的连续原始录屏：先选择一个真实已学词，再切换到其他 App 并展示同一个词。
- [ ] `B03` 保留错词重现的连续会话。
- [ ] 前 9 秒实际出现其他 App、桌宠与真实已学词卡；画面或旁白明确“词源：已学词”和“不读屏”。
- [ ] 视频不暗示桌宠会读取当前屏幕、识别使用内容或根据当前 App 推荐单词。
- [ ] 统计、云端评分和专项练习不作为首发的功能巡展；后续视频只使用真实操作和真实服务端结果。
- [ ] 支付页、真题、二维码、静态排名、未开放模式、私人通知、联系方式、下载鉴权参数和账号敏感信息均未出镜。
- [ ] 其他 App 画面无版权争议和隐私内容。

## 4. 成片与封面

- [ ] 成片 16:9、约 1:25，竖屏录屏未拉伸，字幕每屏不超过两行。
- [ ] 0:15-0:30 出现选词到同一词卡的一镜到底实验；1:10-1:25 才出现 Android 内测 CTA。
- [ ] 每个加速镜头标注真实倍率；关键功能结果保留正常速度画面。
- [ ] 字幕、旁白、画面功能逐项一致，且不超出 `claim-check.md` 的表述。
- [ ] 封面使用真实跨 App 桌宠与单词卡截图，主文案为“背过的词 / 跟着我刷手机”，小标为“词源：已学词”。
- [ ] 用 5 至 8 名目标用户做盲测，至少 4 人能在不看标题说明的情况下说出“桌宠在其他 App 上展示已学词”。若不能，重做截图裁切或标题。
- [ ] `cover/cover-final.png` 为 1920 x 1080，不含 `DRAFT`、占位符或“替换实机截图”提示；在手机和电脑各完整播放一遍成片，声音、字幕、小字和隐私均通过检查。

## 5. 投稿与招募

- [ ] 账号名和简介已按 `publish-copy.md` 更新，分区为“科技 > 软件应用”。
- [ ] 简介真实说明 Android 版本、悬浮窗权限、体验权益、联网边界和评分次数限制。
- [ ] 置顶评论使用“首轮 Android 内测开放中”，不显示虚构或 `0/50` 进度；公开只收“内测”，机型和系统版本只在回复或私信中收集。
- [ ] 不得索取联系方式、密码、验证码，也不要求关注、点赞、投币、转发或三连。
- [ ] 投稿时间选择在开发者能连续回复 1 至 2 小时的窗口。工作日 19:30 至 22:30 可以作为首次测试时段，但不是平台承诺的“最佳时间”。
- [ ] 私信中的版本号、版本代码、下载地址和 SHA-256 与 `release-info.txt` 完全一致；下载页稳定、可撤回旧版本，不使用来源不明的临时分发。
- [ ] 已运行 `./doc/bilibili_launch/validate.ps1 -Mode Release` 并得到 `PASS`。

## 6. 发布后 7 天

- [ ] 在 +1 小时、+6 小时、+24 小时、+72 小时和 +7 天记录曝光、播放、3 秒留存、30 秒留存、平均观看、评论、私信、下载、首次开启桌宠、D3 留存和有效反馈。
- [ ] 前 500 播放不对选题下结论；以同一版本、同一封面或标题的自然数据为基线，一次只改变一个变量。
- [ ] 内部首发诊断阈值（不是 Bilibili 官方门槛）：3 秒留存不低于 75%，30 秒留存不低于 55%，平均观看不低于 40%，有效报名不低于播放的 1%，分享不低于播放的 0.3%。
- [ ] 曝光高但播放低，优先查封面和标题；播放有但 3 秒掉，查首帧是否兑现承诺；30 秒掉，查实验和学习闭环是否足够紧凑；报名多但安装少，查侧载 APK 的信任、权限和下载说明。
- [ ] 达到 50 个有效申请或满 7 天后，更新置顶评论并停止继续发包；至少收集 10 份包含机型、系统版本、复现步骤的有效反馈。
- [ ] 下一期迭代视频只使用已经授权且完成匿名处理的反馈材料。
